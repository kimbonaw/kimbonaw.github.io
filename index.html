DurMI : 음소 duration 기반 TTS 학습 데이터 판별

한국연구재단

특허 2건 출원 TTSDIFFUSIONPYTORCHDIFFERENTIAL PRIVACY
2024.03 – 2025.12
PROBLEM

음성 합성 모델은 학습에 사용한 화자의 목소리를 그대로 재현할 수 있어 개인정보 유출 문제로 이어집니다. 기존 판별 방법은 특정 아키텍처에 종속적이었고, 디코더의 디노이징 과정을 전부 수행해야 해서 추론 비용이 컸습니다.

APPROACH
  • Diffusion·Transformer·Flow-matching TTS에 공통으로 존재하는 음소 duration을 멤버십 신호로 활용해 아키텍처 비종속 방법 설계
  • LLM 대상으로는 데이터 추출과 멤버십 추론을 2단계로 통합(TDE-MIA), logits 없이 토큰 확률 패턴만으로 동작하는 평가 기법 구현
  • Differential Privacy 기반 방어 기법을 적용해 대응 가능성까지 정량 분석
RESULT
추론 속도 약 100배 단축 판별 정확도 평균 +10% 특허 국내 1 · PCT 1 출원 논문 IEEE TETC · TIFS 투고
STACK

Python · PyTorch · Librosa · torchaudio · Llama · Pythia · MFCC / Mel Spectrogram · Differential Privacy

LEARNED

속도 개선은 새로운 모델을 설계해서가 아니라, 판별에 필요한 신호가 이미 인코더 단계에 존재한다는 점을 확인한 데서 나왔습니다. 모델 내부 구조를 끝까지 확인하면 더 낮은 비용으로 문제를 정의할 수 있다는 점을 배웠습니다.

RESULT

보청기 환경 음성 명료도 예측 모델 : Clarity Challenge (CPC3)

The 6th Clarity Workshop 2025

WHISPERASRCNN-TRANSFORMERTORCHAUDIO
2025.05 – 08
PROBLEM

소음 환경에서 보청기 사용자가 음성을 얼마나 인지하는지 예측하는 과제입니다. 기존 방식은 원본 음성과 보청기 출력을 비교해야 했으나 실제 환경에서는 원본을 확보할 수 없고, 범용 ASR 모델은 보청기 출력 특성과 청각장애인의 청취 특성을 반영하지 못했습니다.

APPROACH
RESULT

원본 음성 없이 보청기 출력만으로 명료도를 예측하는 모델을 구현해 전체 참가 팀 중 6위를 기록했고, 결과를 정리한 논문이 Clarity 2025 워크샵에 채택되어 발표했습니다.

STACK

Python · PyTorch · Whisper · CNN-Transformer · Librosa · torchaudio · MFCC / Mel Spectrogram

LEARNED

규모가 큰 사전학습 모델을 그대로 사용하는 것보다, 실제 사용 환경 데이터로 도메인 적응을 수행한 쪽이 성능 차이를 만들었습니다. 원본 음성을 확보할 수 없다는 제약을 먼저 정의하고 그에 맞춰 설계를 시작하는 순서를 배웠습니다.

제조 · 후판 공정

Scale 불량 예측 및 영향 요인 분석

후판 압연·가열 공정의 온도·시간 설비 로그를 활용해 Scale 불량 발생 여부를 예측하고, 불량을 유발하는 공정 변수를 규명한 프로젝트입니다.

IQR·도메인 기준 이상치 제거와 VIF 다중공선성 검증을 거쳐 파생변수(Temp_Diff_Rolling)를 설계하고, 7개 모델을 비교해 Gradient Boosting을 채택했습니다. Feature Importance 분석으로 Rolling·Furnace Soak Temperature를 핵심 인자로 도출하고 공정 개선안을 제안했습니다.

7개 모델 비교DT · RF · GBM · XGB · LGBM · KNN · MLP

Scikit-learn · XGBoost · LightGBM
VIF Analysis · Feature Importance

제조 · 스테인리스강

STS304 M급 불량 원인 분석 및 공정 최적화

스테인리스강(STS304) 생산 이력 데이터 23,632건을 활용해 M급 불량의 원인 변수를 규명하고 공정 관리 기준을 수립한 프로젝트입니다.

Chi-Square·t-Test·ANOVA·Mann-Whitney U 등 통계 검정과 KDE·Box Plot 분포 분석으로 후보 변수를 선별하고, 모델 비교를 거쳐 Random Forest 기반으로 Vital Few를 도출했습니다. 이를 바탕으로 공정 관리 기준과 개선안을 수립했습니다.
